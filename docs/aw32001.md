# aw32001

ESPHome external component for the Awinic AW32001 single-cell Li-ion charger with power path (I2C, 7-bit address 0x49).
Written for Arduino Nesso N1 (ESP32-C6, shared I2C bus SDA GPIO10 / SCL GPIO8, 250 mAh LiPo).

## Registers used


| Reg | Bits | Field | Use |
|---|---|---|---|
| 00 | 7:4 / 3:0 | VIN_MIN / IIN_LIM | `vindpm` (3.88 V + n*80 mV), `input_current_limit` (50, 80, 110 ... 500 mA table; 550 mA = code 15 + REG0C[7] EN0P55) |
| 01 | 4 / 3 | EN_HIZ / CEB | `hiz` switch / `charge_enable` switch and `charge_enabled`. CEB is active low and **resets to 1 = charge disabled** |
| 02 | 5:0 / 6 / 7 | ICHG / WD_TMR_RST / REG_RST | `fast_charge_current` (8 mA * (n+1), max 456 mA at 0x38), watchdog kick. Bit 7 (reset of all registers) is never written as 1 |
| 03 | 3:0 | ITERM | `termination_current` (1 + 2n mA, 1..31 mA). In the datasheet default mode pre-charge current equals this value |
| 04 | 7:2 | VBAT_REG | `charge_voltage` (3.600 V + n*15 mV, capped at 4.2 V here although the chip allows 4.545 V) |
| 05 | 6:5 | WATCHDOG | `watchdog` (00 off = component default, 01 40 s, 10 80 s, 11 160 s = chip default) |
| 06 | 5 | FET_DIS | `ship_mode` switch |
| 08 | all | status | 7 watchdog fault, 6:5 reserved, 4:3 CHG_STAT (00 idle, 01 pre, 10 charge, 11 done), 2 PPM_STAT, 1 PG_STAT, 0 THERM_STAT |
| 09 | 5:0 | faults | 5 VIN_FAULT, 4 THEM_SD, 3 BAT_FAULT (battery OVP), 2 STMR_FAULT, 1 NTC_FAULT hot, 0 NTC_FAULT cold. Bits 7:6 are the shipping-mode deglitch setting, not a status |
| 0A | 7:0 | CHIP ID | reset 0x49 |
| 0B | 5 / 4:1 | EN_IPRE_SET / IPRE | `precharge_current` (1 + 2n mA); setting it switches pre-charge from REG03 to REG0B |
| 0C | 7 | EN0P55 | 550 mA input limit |

## Configuration

```yaml
i2c:
  sda: GPIO10
  scl:
    number: GPIO8
    ignore_strapping_warning: true

aw32001:
  id: charger
  address: 0x49          # default
  update_interval: 30s   # default
  charge_enabled: true   # CEB defaults to "disabled" on this chip
  fast_charge_current: 128mA      # multiple of 8 mA, 8..456
  termination_current: 11mA       # odd, 1..31
  precharge_current: 3mA          # odd, 1..31
  charge_voltage: 4.2V            # 3.6 V + n*15 mV
  input_current_limit: 500mA
  vindpm: 4.52V                   # 3.88 V + n*80 mV, at least charge_voltage + 250 mV
  watchdog: disabled              # disabled (default) | 40s | 80s | 160s
```

Every key is optional.
An unset key leaves the chip value untouched, except `watchdog`, which is always written (`disabled` unless set).
`vindpm` must be at least 250 mV above `charge_voltage` (4.2 V when unset), as the datasheet requires, so 4.52 V or more with the 4.2 V maximum.
`charge_enabled` is written last, after all other settings, so charging never starts with the chip defaults.
Setup checks the chip ID in REG0A first and marks the component failed (`Wrong chip ID`) when another device answers at the address, so nothing is written into it.
The first poll runs at the end of `setup()`: it writes the settings and gives the entities a state at boot.
The writes stop at the first one that fails, so `charge_enabled` never follows a setting that was not written.
Every poll tries again until all of them are written, and the component shows a warning until then.
The default charge current of the chip (about 0.5C of 250 mAh).
The chip allows up to 4.545 V, but this component caps it at 4.2 V because the Nesso N1 cell is a standard 4.2 V LiPo.

Sub-platforms (all keyed by `aw32001_id`):

- `binary_sensor`: `power_good`, `charging` (pre-charge or fast charge), `charge_done`, `power_path_regulation`, `thermal_regulation`, `watchdog_fault`, `input_fault`, `thermal_shutdown`, `battery_ovp`, `safety_timer_fault`, `ntc_hot`, `ntc_cold`, `fault` (any of the fault bits).
  Every status and fault bit has its own sensor.
- `text_sensor`: `charge_status` (`not_charging`, `pre_charge`, `fast_charge`, `charge_done`), `faults` (comma list of active faults or `none`).
- `switch`: `charge_enable`, `hiz` (input high impedance), `ship_mode`.
- Action `aw32001.kick_watchdog: charger`.

The switches only write their bit, and show the new state only when the write succeeded.
Every poll shows the state the chip reports.
A switch is not a component of its own, the hub polls it, so it has no `setup_priority` option.

There is no separate "VBUS present" bit.
`power_good` (REG08[1]) is the input-present indicator, and `input_fault` reports OVP or a bad source.
The component does not use the VIN-detect expander pin.

## Watchdog

The chip boots with a 160 s watchdog.
It runs only while VIN is present; in discharge mode it is off unless REG05[7] EN_WD_DISCHG is set.
When it expires, **both Q1 (input) and Q2 (battery) are switched off**, so the system rail loses power and the ESP resets.
They come back after tRST_DUR (4 s by default), and most registers (charge current, voltage, charge enable, ...) are at their power-on values (datasheet pp. 25-26 and 30).
Deep sleep longer than the period or a stalled main loop on USB power will therefore power-cycle the board.

The component disables the watchdog by default, as M5Unified does for the Nesso N1 (it clears REG05[7:5] at boot).
Opt in deliberately:

- `watchdog: disabled` (default): no kick traffic and no fallback to defaults.
  The safety timers still run.
- `watchdog: 160s` / `80s` / `40s`: the poll writes the kick bit every `update_interval`.
  `update_interval` must be at most half of the watchdog period, else config validation fails.
  This way one missed poll does not let the watchdog expire.
  A poll whose status read fails still tries to kick the watchdog.
  A failed kick sets the warning status of the component.
  If the ESP stalls longer than the period, the board is power-cycled.
  At the next boot `setup()` applies the configuration again, and a poll that still sees REG08[7] applies it once more.

I2C traffic per poll: REG08, REG09, optional REG01 and REG06 for switches, plus the kick (read + write).
Raise `update_interval` to reduce load, within the watchdog limit.
Reading REG09 clears latched faults (NTC bits are not latched), so a poll consumes them.
The sensors show what was latched since the previous poll.

## Logging

At `VERBOSE` each poll logs the raw REG08 status and REG09 fault bytes.
Every register write, including the watchdog kick, is logged by the `i2c` tag at `VERBOSE`, with the value read and the value written.
`dump_config` lists the register settings as register, mask and value.
Set the levels with `logger: logs: aw32001: VERBOSE` and `i2c: VERBOSE`.
The global `logger: level` must be at least as verbose as the tag, so keep `initial_level` at `DEBUG` to leave the other tags quiet.

## Safety notes

- `ship_mode` writes FET_DIS: the battery is disconnected from the system after the deglitch delay (1 s default; 2 s with VIN present, taking effect once VIN is below UVLO).
  Waking needs the adapter plugged in or INT held low for 2 s.
  Restore mode is `DISABLED`; the switch never writes at boot.
- Switch restore mode is `DISABLED` for all three, and the switches never write at boot, whatever `restore_mode` says.
  Use `charge_enabled` in the hub to set the boot state.

## Verified on the Nesso N1

- The register fields used here were checked against the AW32001E V1.2 datasheet (the part on the Nesso N1 is AW32001ECSR).
- Charging works with `charge_enabled: true` and `fast_charge_current: 96mA`.
  The fuel gauge measured 96 to 97 mA into the battery, `power_good` was set, the status read `0x52`, `charge_status` showed `fast_charge`, and the fault register stayed at `0x00`.
- The settings are written in the intended order: the charge current, the watchdog, and the charge enable last.

## Tests

`tests/components/aw32001/test.esp32-idf.yaml` is a build test with every option, entity and action, and two chargers.
Build it from the repository root with `esphome compile tests/components/aw32001/test.esp32-idf.yaml`.

There is no host test any more: `aw32001_regs.h` and its `static_assert` tests are gone.
The code generator now works out every register byte, and the C++ left is single bit tests and a list of names.

The driver allocates nothing on the heap while it runs.
The register settings are a table in flash, made by the code generator with one entry per register.
The binary and text sensors and the switches get their state from a function the code generator writes for each charger, so the charger keeps no list of them.
The `faults` text is built in a buffer of a fixed size.

## Open questions

- Whether the board wires INT is unknown.
  INT is needed for shipping-mode wake and the INT-low reset.
  M5Unified does not use INT or ship mode on the Nesso N1, and the Arduino core only names a shared `SYS_IRQ` on GPIO3 without saying which devices pull it.
- The vendors do not agree on a charge current.
  M5Unified uses 100 mA, the Arduino core 256 mA, which is about 1C for the 250 mAh cell, and the chip default is 128 mA.
  The example board config uses 96 mA.
- Whether the board wires the NTC pin is unknown, and neither M5Unified nor the Arduino core touches the NTC settings.
  The charger has `PCB_OTP` on by default, and nothing here limits charging at a high temperature.
  The fuel gauge reported about 46 °C, which is its chip temperature, while charging.
- The end of a charge has not been seen yet.
  The charger was still in `fast_charge` at 6 mA, and the termination current is the chip default of 3 mA.
- The switches `hiz` and `ship_mode`, the fault sensors and the watchdog have not been exercised on hardware.
  Burst reads and the `REG03` pre-charge/termination coupling were read from the datasheet, and are not used or tested.
